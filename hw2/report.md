## 1. Задача и место верификатора

`[написано]` В проекте по RNA-seq-данным (56 200 генов × 6 047 образцов; ткани зашифрованы номерами 1–5) определяется, какая ткань скрыта под каждым номером. Конвейер: log2(CPM+1) → 3 000 самых вариабельных генов → PCA(50) → логистическая регрессия, оценка 5-кратной стратифицированной кросс-валидацией. Проверяется именно этот кусок: нормировка, отбор генов, разбиение на фолды и оценка качества, а также согласованность исходных данных и итоговой таблицы `results/tissues_result.csv`.

Если здесь ошибка (например, CPM считается по сумме гена, а не образца, или образцы теряются при разбиении), классификатор всё равно может показать точность около 1,0, а вывод «тип 3 = Brain» окажется ненадёжным. Верификатор должен замечать такие ошибки независимо от того, как они повлияли на точность.

## 2. Методика

`[порождено: Claude Sonnet 5.5]`, даты и ревизии данных внесены автором `[написано]`. Методика записана в `hw2/METHOD.md` до первого прогона: замысел, постановка (меняется seed 0–4 и вариант «настоящие/перемешанные метки»; фиксируются данные, конвейер, версии пакетов), ревизия данных по md5, договор о схеме, девять свойств, план из трёх шагов глубины и правило принятия из семи пунктов (порог практической значимости δ = 0,20, парное сравнение по seed, 95 %-ный t-интервал).


## 3. Верификатор

- **Что проверяет:** `[порождено: Claude Sonnet 5.5]` что предобработка и оценка качества в `src/pipeline.py` ведут себя как положено (свойства П1–П9), данные соответствуют договору (С1–С7), а классификатор различает типы лучше случая.
- **Как устроен:** тесты `checks/test_props.py` (свойства, на синтетических данных с известной структурой), `checks/test_contract.py` (договор на данных: по умолчанию на фрагменте `checks/fixtures/` из 100 образцов и 500 генов, на полных данных при `TISSUES_FULL=1`), `scripts/run_experiment.py` (шаги dry, smoke, full с повторами). `src/tissues.py` импортирует функции из `src/pipeline.py`, поэтому проверяется тот код, который считает результат.
- **Чего не проверяет:** см. раздел 8.

Свойства конвейера:

| № | Свойство | Почему должно выполняться | Тест |
|---|---|---|---|
| П1 | умножение каунтов образца на константу не меняет CPM | глубина секвенирования не должна влиять на нормированную экспрессию | `test_p1_scaling_a_sample_does_not_change_cpm` |
| П2 | сумма CPM образца после обратного преобразования равна 10⁶ | сохранение «массы» при нормировке | `test_p2_cpm_conserves_a_million_per_sample` |
| П3 | log2(CPM+1) ∈ [0; log2(10⁶+1)], нулевой каунт даёт 0 | физические границы величины | `test_p3_physical_bounds_and_zero` |
| П4 | перестановка образцов и генов не меняет значения и набор отобранных генов | порядок строк и столбцов не несёт информации | `test_p4_order_of_samples_and_genes_is_irrelevant` |
| П5 | фолды — стратифицированное разбиение: каждый образец в test один раз, train и test не пересекаются, в каждом test все классы | нет потери и утечки образцов | `test_p5_folds_are_a_stratified_partition` |
| П6 | вероятности классов в [0; 1] и в сумме дают 1 | вероятностный выход | `test_p6_probabilities_are_a_distribution` |
| П7 | тот же seed — тот же результат | воспроизводимость | `test_p7_same_seed_gives_same_result` |
| П8 | рост каунта гена в образце не уменьшает его CPM | монотонность | `test_p8_more_reads_of_a_gene_never_lower_its_cpm` |
| П9 | отрицательный контроль: на синтетике настоящие метки ≥ 0,95, перемешанные ≤ 0,55 | конвейер не «угадывает» метки по артефактам | `test_p9_negative_control_labels_matter` |

Договор о данных:

| № | Правило |
|---|---|
| С1 | каунты конечные, неотрицательные, целые |
| С2 | id генов и образцов уникальны и не пусты |
| С3 | у каждого образца сумма каунтов > 0 |
| С4 | метки — целые 1…5, без пропусков |
| С5 | множества образцов в каунтах и метаданных совпадают |
| С6 | представлены все пять типов; на полных данных размеры 1809 / 578 / 2642 / 929 / 89 |
| С7 | в `tissues_result.csv` каждому типу соответствует ровно одна ткань, разным типам — разные ткани; образцы не повторяются |

## 8. Ограничения

`[порождено: Claude Sonnet 5.5]`

- Точность настоящих меток равна 1,0000 при всех seed (sd = 0): классы разделяются идеально, поэтому сравнение с перемешанными метками слабое. Оно доказывает, что конвейер находит сигнал, но не отличает хороший конвейер от безупречно ошибочного. Для этого и нужны свойства П1–П8.
- Отбор 3 000 генов по дисперсии выполняется на всех образцах до кросс-валидации. Метки в нём не используются, но это не вложенная валидация.
- Имена тканей (Skin, Lung, Brain, Blood, Kidney) верификатором не проверяются: точность говорит об отделимости типов, а не о правильности имён. Проверка по маркерным генам выполнена отдельно в проекте и в этот верификатор не входит.
- Свойства П1–П9 проверены на синтетических данных с известной структурой; пограничные случаи реальных каунтов (очень низкие библиотеки, нулевые гены во всех образцах) они не покрывают.
- Seed задаёт разбиение на фолды, инициализацию PCA и перестановку меток, но не данные: разброс отражает вариацию разбиений, а не вариацию популяции образцов. Пять повторов — минимум для t-интервала.
- Порог δ = 0,20 выбран до прогона, не выведен из предметной области; запас до наблюдаемой разности большой.
- Верификатор проверяет `src/pipeline.py` и график интегрирован в `src/tissues.py` по импорту; маркерные гены и генерация графиков в `tissues.py` тестами не покрыты.
- Фрагмент данных для проверяющего (100 образцов, 500 генов) мал: интервалы на нём шире, чем на полных данных.
